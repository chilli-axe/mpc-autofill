Thank you for considering a contribution to MPC Autofill!

## AI Policy

The software development landscape has changed rapidly since early 2025 with rapid advances in AI and this extends to the social norms around contributing to open source projects.

Our stance is that AI-assisted/driven development workflows can be extremely powerful when wielded properly and are almost certainly here to stay. However, they must not replace your own understanding of the changes you're making or communication between humans.

## Commit Messages & Pull Request Descriptions

Pull request descriptions must be authored by hand, not AI-generated. They are a mechanism for communicating the intent behind a set of changes human-to-human. If we wish to read an AI-generated summary of the changes being made, we are more than capable of directing our own AI agents to produce such a summary. AI summaries of changes are unnecessarily verbose, over-utilise bombastic language, and include unnecessary details (e.g. the PR description stating the tests pass on your machine when CI checks pass is redundant). If your PR description is AI-generated I will not read it.

We consider dropping an AI summary of changes into a PR description to be disrespectful of the reviewer's time and intelligence. Don't do this!

## Alignment on Large Feature Changes

Before starting work on medium-to-large feature changes for the project, please reach out to us to seek alignment on the change you're intending to make. Do this by opening an Issue in the GitHub repo. This is not necessary if the changes you're making are obviously a bugfix or are tracked in an open Issue.
