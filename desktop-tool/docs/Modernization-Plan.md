# Desktop modernization plan

Base: DTC release `dtc-v1.2.4`, commit `4b0054939b06c2b6ae9d9fbb0498940d0a67a1f2`. Implementation branch: `feature/dtc-python314-modernization` in its own worktree. No release or merge is part of this work.

## Implementation

1. Pin desktop Python 3.14.9 and uv 0.13.5, with a desktop-local lock and runtime/dev/build groups. Export all groups for the existing pip developer workflow, constrain isolated build backends, and test a clean-cache installation.
2. Update the audited runtime packages. Replace oauth2client with Google service-account credentials, remove unused OAuth and direct Colorama dependencies, and retain setuptools for undetected-chromedriver. Prove real key loading/signing and transport construction offline, including per-thread client reuse.
3. Use wakepy's `keep.presenting(on_fail="warn")` and actual `Mode.active` property for truthful logging. Bypass inhibition with `--allowsleep`, test cleanup on exceptions, and include the current Linux Jeepney adapter in bundles.
4. Enforce Ghostscript 10.05+ at preflight and conversion. Select a supported executable despite an older PATH installation; carry that exact path through conversion and cache fingerprinting. Permit at most one consented automatic installation attempt. Verify installer/source checksums and keep the supported macOS installer at its actual independently published version.
5. Isolate current desktop Ruff, Black, isort, and mypy from the backend Python/Django environment. Preserve strict typing and formatting conventions; remediate obsolete ignores, accurate annotations, necessary narrowing, and documented third-party typing exceptions. Provision both interpreters and pinned uv in shared pre-commit CI.
6. Compile with locked `python -m nuitka`, preserving onefile data, TLS, version, all four architectures, signing, and notarization. Share repeated setup/compiler steps while retaining separate signed/unsigned orchestration. Keep the Ubuntu 22.04 Linux build baseline.
7. Validate actual PDF rendering/profile/layout and reuse/rebuild, real UC startup on local fixtures, dependency advisories, workflow structure, Linux onefile compilation, and execution in clean Debian 12. Independently review the implementation and resolve substantive findings before committing.

## Independent plan reviews

Three reviewers independently inspected the draft and code, focusing on runtime compatibility, release/packaging safety, and scope/testing. All requested amendments. A fourth readiness review checked the revised contract and found one final API correction. Accepted amendments:

- Standard Selenium checks were insufficient: add real account-free `get_undetected_chrome_driver` startup coverage. Live challenges and authentication remain separate manual checks.
- Wakepy can warn and continue: report success only after actual activation. The final reviewer caught that version 1.0.0 exposes `active` and `result.success`, not `Mode.success`; the corrected API was verified against a real Mode.
- Runtime setuptools does not constrain isolated builds. Add build constraints and clean-cache verification; use explicit group selections for sync, run, and export.
- Handle a supported Ghostscript installation shadowed by an older executable. Pass the validated path through existing configuration and guard direct conversion callers too.
- PDF labels cannot reveal blank, cropped, or reversed pages. Render the result and check physical dimensions, face order, nonblank artwork, and embedded profile bytes, without claiming formal conformance validation.
- Shared pre-commit callers need uv and desktop Python. Explicit hook filters/configuration prevent desktop-only changes from invoking backend mypy; preserve backend Python 3.13.
- Verify final signed artifacts and accepted notarization. Test actual Linux execution in Debian 12 rather than inferring compatibility from the builder.

The reviewers differed on whole-workflow consolidation. The smaller selected change shares composite setup/compiler actions and keeps signing orchestration in its existing workflows. A broad formatter/framework rewrite, changing the SWOP print target, and free-threaded Python were deferred.

## Acceptance and limits

Run locked synchronization/export freshness, clean-cache runtime installation, dependency advisory scan, desktop style/type checks, existing tests plus offline regressions, local Chrome/UC tests, source/bundled TLS/help/PDF smoke, architecture checks, and clean Debian 12 execution. Run repository-wide pre-commit and distinguish unrelated baseline failures from desktop regressions.

Windows/macOS compilation and signing require native CI runners and secrets. Headless tests demonstrate wakepy fallback/import completeness, not physical sleep behavior. Local fixture tests do not prove DTC bot-protection compatibility. Test bundles with synthetic credentials cannot perform live Drive downloads; release builds must use the existing service-account secret. Do not publish test artifacts as releases.

## Related color-benchmark evidence

The separate private `bwsinger/card-color-benchmark` study provides additional release context. Its saved desktop control uses the DTC v1.2.4 Linux artifact, SHA256 `6255b85adad77632c42b370277f39283c00eba7bd9f78c6a7471334435fae326`. The accepted core results are frozen at SHA256 `d0074924a747894d4fed98267f3102a0a06892ce67a4a4c5fcc4d1064f530133`; do not rerun or rewrite the old matrix, scores, or reference normalization when checking this upgrade.

The study shows why functional PDF checks are insufficient to establish print-color equivalence: JPEG encoding can push final decoded CMYK samples over the 240% total-ink ceiling, while alternative profiles/encoders can trade shadow detail and upload size for ink compliance. A cleared DTC PDF checker warning establishes neither ink compliance nor physical fidelity. Keep the existing SWOP profile and conversion/compression settings; the separate ink-limiter work does not automatically change production defaults.

The frozen benchmark encoder is Pillow 11.0.0 / libjpeg-turbo 3.0.4; the modernized Linux environment uses Pillow 13.0.0 / libjpeg-turbo 3.2.0. Old numerical scores therefore do not certify this stack, even with unchanged application settings. Color/output equivalence remains unverified by the modernization's synthetic layout smoke.

The color-regression bridge generated only new-stack outputs for six fixed cases: Urza's Saga, Enlightened Tutor, Disciple of Freyalise, alpha-composite, wide-gamut-chart, and dark-ramp. All 12 faces matched the stored actual-desktop controls exactly in source JPEG bytes, final image streams, decoded CMYK, geometry, face order, profiles, and stream/order-PDF sizes. Independent Poppler decoding of the 24 old/new pages agreed exactly. Input, software, binary, profile and output hashes and commands are recorded in `/tmp/dtc-modernization-color-bridge-20261024-vACPGiIF`. Frozen controls and scores were not regenerated or changed. The different private Ghostscript binary produced identical selected outputs; existing ink overshoots were unchanged.

The strict integer boundary (sum 612 passes, 613 fails) was verified. The separate limiter study's zero-overinking and maximum 10% growth goals are candidate-screening criteria, not results achieved by this modernization. The six-case match establishes equivalence only for those inputs; full-corpus testing was skipped, and saved CMYK-input controls were unavailable. Physical proofing and formal PDF/X validation remain separate checks.

PR #11 was merged at `3f04f1af` and integrated with the locked compiler. Both build entry points retain its version/repository metadata and unique repository/run/attempt/target product identity. The combined Linux source suite passed 258 tests with 30 credential/release-gated skips; repository-wide pre-commit and source PDF smoke passed. Two independent integration reviews and a final review of CI corrections found no substantive code issues.

The first native run exposed a Windows checkout newline mismatch in the export freshness check. Text comparison now normalizes line endings while retaining exact dependency comparison, verified independently. The next run exercised credential-backed image downloads on Windows and Apple silicon macOS and exposed two old PNG byte-size assertions. Their source fixture (SHA256 `f4231d8c277241b247ccb1056c476d55c21d85adf4a7d898d87d9bb69f785487`) and its 100-DPI Lanczos result have identical decoded pixels under Pillow 11 and 13, despite platform-dependent PNG compression. Those assertions now verify PNG/RGB format, exact dimensions, and exact decoded pixel hashes; the unprocessed-download byte-size contract remains intact.

Native qualification requires two successful builds of the same test version and commit on Windows, Linux, and both Mac architectures, followed by the supplied 52 packaged startup/consent/replacement scenarios. The existing build workflow can route validation inputs to the reusable package-check workflow before its file is registered on the default branch. Validate the final release metadata and actual merged-commit assets separately. Signing credentials are not configured in this fork; publish and describe these assets as unsigned.

Native Ghostscript upgrade acceptance passed on disposable runners: Windows 10.04.0 to 10.08.0, both Mac architectures 10.04.0 to 10.07.1, and Linux 9.55.0 to private 10.08.0. The checks verified downloads, available installer signatures, old-first PATH recovery, actual PDF rendering/profile/layout, and cache reuse/rebuild. Linux also rejected a zero-exit apt installation that remained unsupported. Windows passed [run 40111863698](https://github.com/bwsinger/mpc-autofill/actions/runs/40111863698); the successful Mac/Linux jobs are in [run 40111354731](https://github.com/bwsinger/mpc-autofill/actions/runs/40111354731), whose overall failure was an earlier Windows unattended-installer attempt. Cancellation/elevation-denial unit regressions are included in the production test suite.

The native onefile build exposed a distribution-specific Python 3.14 Zstandard limitation after successful C compilation: GitHub's Linux Python supports zero background compression workers, while Nuitka requested four. CI now probes the actual compressor and verifies a round-trip before compiling. It selects Nuitka's low-memory payload mode only when the library supports zero workers, preserving parallel C jobs. This changes executable-payload compression level only; image and PDF settings are unchanged. Build matrices retain independent results after a platform failure. Fresh complete native package qualification remains required after this correction.
